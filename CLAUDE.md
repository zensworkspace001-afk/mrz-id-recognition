# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

ID-document recognition pipeline for passports from 8 countries/regions (JPN, CHN, HKG, KOR, VNM, IDN, PHL, IND) and the Taiwan Alien Resident Certificate (ARC). Code comments, docstrings, CLI output and review-reason strings are in Traditional Chinese — keep new ones consistent.

Two dependency sets. **Local** (`requirements-local.txt`): `.venv/bin/pip install -r requirements-local.txt`, `brew install tesseract cmake`, then `scripts/build_opencv.sh` — OpenCV is **built from source** (core/imgproc/imgcodecs only, no FFmpeg/videoio) because the pip `opencv-python*` wheels bundle GPL x264/x265. Never add `opencv-python` to `requirements-local.txt`; `TestLicense` fails if the loaded cv2 has video backends. **Cloud / Vercel** (`requirements.txt`, which Vercel installs automatically) deliberately uses pip `opencv-python-headless` + `tesserocr` (bundles the Tesseract engine) — server-side only, not distributed (THIRD_PARTY_NOTICES §6); set `IDPIPE_ALLOW_PIP_OPENCV=1` there to skip `TestLicense`. Only use cv2 functions from core/imgproc/imgcodecs (no `VideoCapture`, `imshow`, etc.); a new module means editing `BUILD_LIST` in the script and `THIRD_PARTY_NOTICES.md`. On this machine everything lives in `.venv/` — use `.venv/bin/python` in place of `python3` below.

`synth/render.py` prefers Linux DejaVu fonts and falls back to macOS Andale Mono / Arial, so synthetic images rendered on different OSes are not pixel-identical.

## Commands

```
python3 -m unittest discover -s tests                     # all tests
```

## Architecture

Flow: detect corners → rectify → OCR the MRZ → route to template → visual-zone (VIZ) extraction → merge MRZ/VIZ → validate/cross-check → `needs_review` → storage.

- **`idpipe/pipeline.py`** is the core. `Pipeline` takes a `Components` dataclass of injectable callables (`rectify`, `ocr_text`, `viz_extract`, `classifier`). Defaults are no-op stubs, so tests and early runs work without trained models. `run.py` wires in the real parts: `auto_rectify` → `rectify_details` (see Rectification below) and `ocr.ocr_mrz_region`. Without `--synth-layout`, `viz_extract` stays a no-op (no calibrated regions), so real runs only fill fields that come from the MRZ.
- **MRZ is the source of truth.** `mrz.py` parses TD3 (passports, 2×44) and TD1 (cards, 3×30) with ICAO check digits; `parse_mrz(lines)` dispatches on line count and `find_mrz_lines` returns 2 or 3 lines. Callers should use `parse_mrz` / `MrzResult.name_field` / `name_line_index` rather than assuming TD3. `find_mrz_lines` repairs OCR noise by field position (O/0, I/1 etc. via `_fix_line2`), rebuilds line 2 when OCR drops or adds `<` fillers (`_rebuild_line2`), and `repair_document_number` tries character swaps. `build_td3` generates valid MRZs for the synth data and tests. `ocr.ocr_mrz_region` OCRs only the bottom ~32% of the rectified image (retrying at 45% for cards, whose TD1 block sits higher) with each preprocessing in `MRZ_VARIANTS` (sharpening / adaptive threshold help blurry photos): line 2 is taken from the first checksum-valid read, line 1 (names, no check digit) by majority vote across variants. `_reconcile_country` fixes one-char misreads of issuing country vs. nationality using the supported country list.
- **Name line has no check digit — three defences** (motivated by real Taiwan passports, where the guilloche background made Tesseract read the 23-char `<` filler as `KKKK…` and inserted/dropped letters in the surname):
  1. `chevron.py`: MRZ is monospace, so the OCR line is re-aligned onto its connected-component glyphs (must be exactly 44 or 30); each glyph is shape-classified as `<` or not (`is_chevron`; digit `4` is the closest look-alike), the OCR string is DP-aligned onto the slots, and each letter run is re-OCR'd alone with a length constraint. On name lines (no digits) the result is used directly. On TD3 line 2 each run is instead re-read with a position-class whitelist (`TD3_LINE2_CLASSES`) and adopted **only if more check digits pass** than the raw OCR — plain alignment there once shifted a document number that still passed its check digit.
  2. `ocr.ocr_mrz_region` collects name-line reads across crops × `MRZ_VARIANTS` (≥3 reads, or 2 identical) and votes per position (`vote_name`).
  3. Ties or a single read set `MrzText.uncertain_name`, which the pipeline turns into the review reason `MRZ 姓名行各次辨識結果不一致`.
  `_ocr_mrz_text` uses `image_to_data` and regroups words into rows by y-position (Tesseract sometimes splits one MRZ line across blocks).
- **Taiwan passport** (`TWN-passport-current`): personal-number field is the national ID; `normalize.taiwan_id_valid` checks its own checksum (also used for new-format ARC UI numbers `[A-Z][89]\d{8}`; the old 2-letter ARC format uses a different algorithm and is not checked).
- **VIZ extraction (`viz.py`)**: `make_viz_extractor(layout)` crops each template region, drops color (per-pixel max channel, removes red watermark / tinted backgrounds), flattens illumination (glare), and OCRs each field with `FIELD_VARIANTS`, taking the first result that passes a per-field format check (`_valid`). Real templates have no regions yet, so `run.py --synth-layout` substitutes `templates.SYNTH_LAYOUT` (the generic synth page) — only valid for `synth/` images.
- **Merge rule**: for fields the MRZ covers (incl. surname/given_names), value and confidence stay MRZ; VIZ is stored as `viz_value` / `viz_confidence` and used only for cross-checking. Names have no MRZ check digit, so the VIZ name cross-check is what catches line-1 OCR errors; prefix matches are allowed only when the MRZ name field is full (truncated). A low-confidence VIZ read never overrides a checksum-valid MRZ field.
- **Rectification (`run.rectify_details`)**: candidates are the corner quad at 0°/180° and the page quad inferred from the MRZ (`locate.py`) in both orientations; each is rectified and probed with `_mrz_score` (quick OCR, `min_reads=1`). First all-checksums-valid wins, else the one with the most passing check digits (≥2), else full image. Corner candidates are skipped when the located MRZ isn't horizontal in the corner-rectified frame (portrait/rotated photos). Returns `(flat, quad, rotated, method)` with method `corners` | `mrz` | `whole`.
- **MRZ locator (`locate.py`)**: blackhat → several thresholds (Otsu + 90/94/97th percentile) → rotate in 5° steps → horizontal closing → pick 2 (TD3) or 3 (TD1) equal-length, left-aligned, evenly spaced bars, each made of ≥`MIN_GLYPHS` separate glyphs (rejects stacked page edges / desk edges, which once outscored the MRZ). Page quad comes from the fixed 2.54 mm character pitch plus `PAGE_GEOMETRY` (margins measured on a real Taiwan passport and the NIA ARC specimen). It cannot tell 0° from 180°; callers try `page_quad(flipped=False/True)`. Handles open booklets, fingers, and any rotation.
- **Corner detection (`detect.py`)**: background = per-channel plane fitted to the image border (handles shadow gradients), then a flat median; the document mask's polygon edges lying on the image border are dropped and the 4 longest remaining sides are line-fitted and intersected, so corners outside the frame are extrapolated. Every candidate must pass `plausible_document` (aspect 1.25–1.8, angles 65–115°); a quad hugging the frame snaps to the full image (already-cropped photos). Evaluate with annotated `corners` in `annotations.jsonl`.
- **Routing (`router.py`)**: the MRZ format + issuing country map to a template via `templates.template_for_mrz` (TD3 → `COUNTRY_TO_PASSPORT`, TD1 → `COUNTRY_TO_CARD`, i.e. TWN → `TWN-arc-current`). The image classifier is only a fallback (min confidence 0.90). If the two disagree, a review reason is added.
- **Templates (`templates.py`)**: one `Template` per document type, keyed like `JPN-passport-current` / `TWN-arc-current`. Field regions are all `None` and `calibrated=False` because they still need to be measured on official samples. Per-country quirks live in `rules`: native-script names are left out of name matching, Vietnamese diacritics are stripped before matching, mononyms, the PHL middle name, and the ARC number regex.
- **Taiwan ARC / Gold Card MRZ** (per NIA specimens, back of card): TD1 `I<TWN…`; the document-number field holds the **passport number**, the UI No. (統一證號, `[A-Z]{2}\d{8}|[A-Z]\d{9}`) sits inside line-1 optional data and is protected only by the composite check digit, and line 3 has no `<<` so the whole name lands in `surname` — names are compared as full names (`mrz_name_unsplit`). Composite check-digit placement is unverified against a real card. MRZ is on the back and VIZ on the front, but the pipeline still processes one image per record.
- **Review logic**: every problem appends a human-readable string to `rec.review_reasons`, and `needs_review = bool(reasons)`. Triggers include checksum failure, VIZ≠MRZ mismatch, confidence below 0.80, unknown template, passport with no MRZ, and a bad ARC number. An ARC image without an MRZ (e.g. the front side) is not flagged for missing MRZ; it relies on VIZ for the UI No.
- **Schema (`schema.py`)**: `DocRecord` is the output contract and the future DB table layout (`SCHEMA_VERSION` is in `idpipe/__init__.py`). `fields` holds per-field `{value, raw, confidence, bbox, source}` with source `mrz` | `viz` | `mrz+viz`. ARC-only data is in the nested `residence`. `doc_id` is the SHA-256 of the image bytes.
- **OCR backend (`idpipe/tess.py`)**: all Tesseract calls go through `tess.image_to_string` / `tess.image_to_data` (pytesseract-compatible). Uses pytesseract when the `tesseract` binary exists, else tesserocr with `tessdata/eng.traineddata`; force with `IDPIPE_OCR_BACKEND`. Both produced identical MRZ results and review decisions on all 80 synth images. Never call pytesseract directly.
- **Vercel (`api/index.py`, `vercel.json`)** — live at https://mrz-id-recognition.vercel.app, deployed with `npx vercel deploy --prod` (project linked in `.vercel/`; not Git-connected, so a push does not deploy): every path rewrites to `/api/index?__route=$1`, because the handler only sees the rewritten path — `serve.route()` restores the original from `__route`. `api/index.py` must `import tesserocr` at module load: its `cysignals` dependency registers signal handlers, which Python only allows on the main thread, and Vercel serves requests on worker threads. `includeFiles` must list runtime-read files (`web/**`, `tessdata/**`). Python 3.12 (`.python-version`); function size is near the 250 MB limit mostly because of opencv-python-headless (~143 MB unzipped). The page detects non-localhost hosts, shows a "don't upload real IDs" banner, offers synthetic samples from `web/samples/` (served via whitelisted `/samples/<name>.jpg`), and downsizes uploads to ≤2400 px client-side to stay under the ~4.5 MB request limit.
- **Local site (`serve.py` + `web/index.html`)**: stdlib `ThreadingHTTPServer` bound to 127.0.0.1; `POST /api/check` runs `quality.check_photo` (~0.5 s, no OCR: MRZ found, char height, Laplacian sharpness, glare, brightness — thresholds calibrated on synth blur levels and real photos) and the page only proceeds to recognition when no check fails (user can force). The page queues multiple files client-side into a staging area (「暫存區」), processes them one at a time, and once nothing is pending exports the checked rows (免複核 pre-checked; checking a 需複核 row marks `reviewed_by_human`) as CSV (browser-side) or SQL via `POST /api/sql` → `sqlexport.to_sql` (PostgreSQL/MySQL/SQL Server/SQLite: `CREATE TABLE IF NOT EXISTS` / `IF OBJECT_ID … CREATE`, then upsert on `doc_id` in one transaction; table name is whitelisted by regex; full record kept in `record_json`). SQLite and MySQL output were executed for real during development; PostgreSQL/SQL Server only syntax-checked; `POST /api/recognize` (raw image bytes, `?synth=1` for `SYNTH_LAYOUT`) runs the full pipeline with `storage=None` (uploads are never written to disk) and returns previews, per-check-digit printed/expected values and the record; `POST /api/mrz` validates pasted MRZ text without OCR corrections. Reuses `run.rectify_details`.
- **Storage (`storage.py`)**: `JsonlStorage` is the primary store. It dedupes by `doc_id` by rewriting the whole file on each save. `SqliteStorage` stores the whole JSON plus a few query columns. `export_csv` flattens records and writes `utf-8-sig` so Excel opens them correctly.
- **Synth (`synth/`)**: renders generic (not country-accurate) passport pages with made-up identities, a SPECIMEN watermark and capture augmentations (angle, blur, glare, shadow). Each image's annotation includes its corners, field polygons and the ground-truth MRZ. It is only valid for training/evaluating corner detection, MRZ OCR and robustness. Synthetic scores do not reflect real-world accuracy, and field templates still need real samples.
